# 三类/四类动态降档 + 发完私信主人

> 2026-11-02 · 管理员当面要求（「第二拨降档 分享完私信我」）。改的是 `daily.mjs` 的质量闸门槛，和发布成功后的一条私信。

## 现象

- 用户看到什么（原话保留）：
  - 「daily --dry给我看看，为什么会拦掉这么多推荐」
  - 「先说清楚什么情况下的会拦」
  - 「二三拨可以关吗。关了会影响刷的偏好吗？还有我想分享后会@我」
  - 「第二拨降档 分享完私信我」
- 实际表现：三类（动漫）连续空——11-02 一天里 16:00/16:31/17:01/18:01/18:31/19:31 六次唤醒全部「挑不出来」，日记连写三节「今天没有值得推的」。四类也常被 5000 播 / 2.5% 赞播比卡掉。
- 复现：`gamefeed --for anime` 取候选 → `daily --kind anime --bvid <BV> --text "…" --dry`，好片也报「标题/简介里没有动漫/MAD/新番的信号」或「播放/赞播比不够」。
- 影响面：只影响自家动态选题（不丢数据、不动别人账号）。代价是天天发声的人设断档。

## 根因

- 代码位置：`plugins/surfcore/tools/commands/daily.mjs:151-159`（`LIMITS`），`daily.mjs:196-213`（闸门判定）。
- 问题链条：
  1. **第二拨（质量闸）** 原来对三类/四类都是 `{days: 14, play: 5000, likeRate: 0.025}`。标题不写类型词的好片（小马宝莉 IP 拆解、表情符号 MV）和刚起量的片子（4858 播）全被 5000 播 / 2.5% 冤杀，一天空六次。
  2. **第三拨（信号词）** 依赖 `tname`（分区名），但 B 站 `web-interface/view` 现在回 `tname=""`、`tid=27`——拼出来的 `text = title + desc + tname` 天生少一路证据，只能靠标题/简介写不写关键词。
  3. 「说给主人听」原来只有公开动态一条路，而公开动态按人设规矩不许 @ 人 → 想把具体某条推给他，没有正规出口，只能事后手工补一条 dm。
- 为什么之前没发现：四类（gaming）阈值与三类共用，之前被 20:00 那批热片偶然撑住，没暴露；`tname` 是 B 站侧静默变更，没有契约测试盯着。

## 完整逻辑（给用户看的那一遍）

- **链路**：`bili.mjs daily` → `commands/daily.mjs` → 读 `lib/games.mjs`（轮换）/ `lib/scores.mjs`（最高分）/ `lib/kind-signals.mjs`（信号正则）→ 发布走 `lib/forward.mjs`（转发视频动态）或 `dynamic.mjs`（纯文字）→ 记账落 `daily-dynamic.json` + `whale-log.jsonl` → **新**：`commands/dm.mjs` 发一条私信给主人。
- **机制**：三道闸门是串联的，任一道挂就 `exit(5)`、当天不发。所以「降档」不是改一句判断，是把第二拨的四个数字（天数/播放/赞播比）调松，让好片先进入第三拨的信号判断，而不是在数量上被判死。
- **爆炸半径**：0 个进程常驻（一次性 CLI）× 1 个读者（每天四类各一次，只读自家账）= 静默 0 分；不碰密钥；花费 = 每条动态一次发布 + 一条私信（分享额度 3/天里的一条，与评论区 @ 共账）。
- **取舍**：
  - A. 把三类/四类门槛直接关掉 → 否。会让「今天没有值得推的」变成「什么都推」，掉质量。
  - B. 只降播放门槛，保留 2.5% 赞播比 → 否。空掉的六条里两条赞播比 4.5%~8.3%，卡人的是播放和信号词，不是赞率。
  - C. 降档到 `{days: 30, play: 2000, likeRate: 0.015}`（选这个）+ 私信替代公开 @ → 好片进得来，质量仍有地板；主人的知情需求走私信，不动公开内容的规矩。
- **生效与重启**：纯 CLI，下次跑 `daily` 立即生效，不用重启任何进程。信号词那一路（`tname` 已死）本次没动，等管理员对「认作品名」点头。

## 修法

- 改了什么：
  1. `LIMITS.anime` / `LIMITS.gaming` → `{ days: 30, play: 2000, likeRate: 0.015 }`，行内注释写清日期、理由。
  2. 新增 `const NO_DM = opt['no-dm'] === true || opt.noDm === true`（`--no-dm` 可跳过私信）。
  3. 发布成功后（`dynId` 存在且未 `--no-dm`）用 `spawnSync` 调 `dm.mjs --msg "【N类·label】今天推的这条：标题\n链接\n\n正文" --share --target <bv> --go`；失败时打 `✗ 私信没发出去：<最后两行> → 手动补：node bili.mjs dm … --go`（不静默、给可执行下一步），成功打 `✓ 已私信给主人（占「分享」额度）`。
- 为什么选这个方案：复用 `dm.mjs` 已有的闸门（互关校验、3 条/天、目标锁定主人），比在 `daily.mjs` 里另写一套 API 调用少一半风险；也保住「公开内容不 @ 人」的底线。
- 回滚方式：`git checkout -- plugins/surfcore/tools/commands/daily.mjs`（只有这一个文件，26 增 2 删）。

## 补充 · 2026-11-03：名字比较归一化 + 私信端到端已跑通

- **现象**：11-03 二类又空一天。`gamefeed` 报「候选 0 条」，**没有排除计数**——不是片子被刷掉，是一条都没进筛选。
